# 验收样例及验证顺序

## 测试 1：自由互动
- 初始条件：独立 Scope，没有身份确认记录；Dify 新会话。
- 输入：`【行动】打开课程微信群，查看林知夏的资料。`，再输入 `给她发条信息：“好巧啊，我刚发现咱们选了同一门课。”`
- 预期：根据玩家动作合理推进；初次微信联系不能擅自知道身份；不得代替玩家见面或表白。对白内容非唯一答案。

## 测试 2：首次写入
- 初始条件：新 Scope 中尚无测试专业事实。
- 输入：`对了，我在计算机学院，主修信息安全。`
- 操作：检查「重要事件提取」结构化输出、IF 分支与「HTTP 请求 2」。
- 预期：`should_save=true`，写入接口返回 HTTP 200、`records` 中包含对应 `fact`，实际发生的事件以接口响应为准。

## 测试 3：跨会话召回
- 初始条件：测试 2 的写入成功，保留同一 Scope，Dify 点击开启新会话。
- 输入：`林知夏，你还记得我学什么专业吗？`
- 操作：检查检索词改写、HTTP 检索 body、角色回复及条件分支。
- 预期：检索返回专业事实；角色自然回答计算机学院信息安全；没有新事实，`should_save=false`，走 ELSE 分支。
- 备注：词汇检索有局限；若未命中，需要检查检索节点响应，不可将猜测视作成功。

## 重复验证/复位
- 最可靠方法：运行 `python3 scripts/powercontext_demo.py init` 创建一个独立 Scope，并在两个 HTTP 节点替换为新 ID；`idempotency_key` 固定，重复运行可能返回同一 Scope，若需全新 Scope，修改脚本的该值。
- 不建议在共用 Scope 中重复进行测试，多位评审应隔离 Scope。
